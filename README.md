# Hypothesis Pack

Набор из 6 методик для формулировки, усиления и проверки бизнес-гипотез. Подходит для продуктовых команд, трекеров стартапов, фасилитаторов и всех, кто работает над «что нам делать дальше».

## Когда использовать

- Усилить слабую или среднюю гипотезу до сильной
- Сгенерировать новую гипотезу под выбранную территорию
- Проверить готовую гипотезу перед запуском пилота
- Найти радикальное усиление через идеальный результат

## Сценарии работы

### Сценарий 1 — Усиление существующей гипотезы
1. **JTBD Fit Check** — проверяем попадание в реальный джоб
2. **ИКР** — ищем идеальный результат, радикализуем
3. **Сет Годин** — усиливаем оффер
4. **RAT** — находим убийственные риски

### Сценарий 2 — Новая гипотеза с нуля
1. **Spot Supertrend** — находим волну
2. **JTBD Fit Check** — определяем джоб клиента
3. **ИКР** — масштабируем до идеального
4. **Сет Годин** — формулируем оффер

### Сценарий 3 — Проверка готовой гипотезы перед пилотом
1. **RAT** — убийственные предположения + killer-эксперимент
2. **Pre-mortem** — что мониторим, что страхуем

## Формат сессии «опрашиваю + показываю»

1. **Опрашиваю** заказчика первым — его мысль, его материал
2. **Запускаю** соответствующую методику с его материалом
3. **Смотрим** результат вместе
4. **Сравниваем** — где сходится, где расходится с первой мыслью
5. **Корректируем** и переходим к следующему шагу

## Что получаем на выходе сессии

- 1-2 готовые сильные гипотезы за сессию
- Понимание метода — какая методика когда применяется
- Возможность повторить процесс самостоятельно
- Материал для презентации руководству / инвесторам

## Шаблон гипотезы

См. [hypothesis-template.md](hypothesis-template.md) — формат:

> Мы верим, что **именно сейчас** [ПОЧЕМУ] есть **возможность** [ЧТО СТАЛО ДОСТУПНО], и если мы сделаем [ЧТО — широко, без впихивания решения], то клиент изменит поведение [КАК], благодаря тому что мы снимем барьер [КАКОЙ БАРЬЕР] в растущем джобе [ДЖОБ].

## Принципы

1. **Гипотеза — про потребность клиента, не про продукт**. Способ реализации придумываем после проверки.
2. **Скиллы дают разные углы**, не один правильный ответ. Каждый видит то, что упустит другой.
3. **Решение в впихивании в формулировку — сужает работу команды** до защиты конкретного продукта.
4. **Радикализация — это исследовательский режим**, не обещание руководству.

## Как использовать с Claude Code

Каждая методика — это инструкция для AI. В Claude Code вызвать как команду (если файл лежит в `.claude/commands/`) или скопировать содержимое в чат и подставить задачу.

## Как использовать без AI

Читать как методологию и применять руками на доске / в Miro / в чате команды.
